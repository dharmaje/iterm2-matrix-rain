# Customize

All settings live in `matrix_rain/defaults.toml`.  Users override them in `~/.config/iterm2-matrix-rain/config.toml`, which needs only the keys that change.  The daemon reads that file at start, so restart it after edits.

1. **Tune a state.**  Each `[states.<name>]` has `background`, `tail` and `head` as RGB, plus `speed` (cells per second), `density` (share of columns active), `brightness` and `mutation`.  Keep changes subtle: a near-black background and heads below about 240 in every channel.
2. **Preview before applying.**  Run `.venv/bin/matrix-rain preview /tmp/rain-<state>.png --state <state>` and read the PNG.  Show it to the user, then write the config.
3. **Window-level settings.**  `[daemon] blend` controls how much image shows through; higher shows more rain, and 0.6 is the default.  `fps` sets the focused-window rate, `idle_interval` the background rate, `transition` the easing time, and `profile` the opt-in profile name.  When `profile` changes, the user's sessions must use a profile with the new name.
4. **Glyphs.**  `[render]` sets `cell_width`, `cell_height`, `font_size`, `glow`, `mirror` and the `fonts` fallback list.  Run `matrix-rain bench` afterward; a frame should stay well under 100 ms.
5. **Add a state.**  Add `[states.<new>]` to `defaults.toml` (transient states also need `hold` and `next`).  Add the name to `STATES` in `matrix_rain/config.py`, and add it to `TRANSIENT` in `matrix_rain/state.py` if it holds.
6. **Map a hook event.**  Edit the `case` in `hooks/claude-code-hook.sh`, then add a row to `HOOK_CASES` in `matrix_rain/selftest.py`.  If Claude Code does not yet call the hook for that event, add it to the `--hooks` block in `install.sh`.
7. **Camera motion tint (optional).**  Ask the user before anything that opens the camera.  Install it with `./install.sh --camera`.  Then `matrix-rain camera test` runs a 10 s live check, which triggers the macOS permission prompt the first time.  `matrix-rain camera enable` or `disable` writes only `[camera] enabled`; restart the daemon afterward.  Tune `tint`, `head_tint`, `fade`, `sensitivity`, `strength`, `fill`, `shape` (`outline` or `fill`), `burst`, `burst_rest`, `burst_strength`, `burst_tint`, `burst_head_tint`, `fps`, `warmup`, `mirror`, `only_when_active` and `device` under `[camera]`.  Preview without a camera with `matrix-rain preview /tmp/m.png --state working --motion-demo`, and check the cost with `matrix-rain bench --motion` (keep it under 20 ms).
8. **Status bar toggles.**  The daemon registers two components, defined as `RAIN` and `CAMERA` in `matrix_rain/statusbar.py`: `us.epel.iterm2-matrix-rain.rain` ("Matrix rain"), whose click calls `Daemon.set_paused` (clears backgrounds, stops rendering, closes the camera, saves `[daemon] paused`), and `us.epel.iterm2-matrix-rain.camera` ("Matrix rain camera"), whose click calls `Daemon.set_camera` and saves `[camera] enabled`.  `matrix-rain pause|resume|toggle` sends the same pause over the event socket.  The Matrix profile's `Status Bar Layout` in `profiles/Matrix.json` carries both, generated from those definitions.  After changing a component, paste the matching entry from `matrix-rain status-component` over it in the profile; selftest checks they match.  Keep each spec's RPC function and argument names as they are, since the saved registration bytes depend on them.  Status bar position is a global iTerm2 setting.
9. Run `matrix-rain selftest` and update the README state table and defaults block.
